## Ejemplo de mala interfaz de usuario
Caso de estudio: [User Inyerface](https://userinyerface.com/), un experimento de peores prácticas de UI creado por Bagaar que sirve para identificar errores comunes de usabilidad, entre ellos:
- El botón **"NO"** de la página inicial no permite comenzar el juego, por lo que el usuario tiene que buscar el enlace escondido en el texto para avanzar
- El enlace para pasar a la siguiente página está integrado en una palabra del texto, en lugar de mostrarse como un botón claramente visible
- El botón **"GO"** aparece dentro de una frase y no tiene un diseño visual que lo diferencie claramente del resto del texto
- Los campos de contraseña tienen requisitos excesivamente específicos, lo que obliga a probar diferentes combinaciones hasta conseguir una contraseña válida
- Se utilizan **etiquetas poco claras** en algunos campos del formulario, lo que dificulta identificar qué información se debe introducir
- Algunos campos obligatorios no se identifican de forma clara antes de intentar enviar el formulario
- Los mensajes de error aparecen después de realizar acciones incorrectas, en lugar de explicar los requisitos antes de rellenar los campos
- El formulario incluye campos y condiciones que hacen que completar el registro sea más largo de lo necesario
- Los elementos interactivos están distribuidos de forma poco habitual, por lo que el usuario tiene que buscar dónde continuar
- Los botones y enlaces utilizan comportamientos diferentes a los habituales, lo que obliga a aprender cómo funciona cada elemento
- Hay opciones que aparecen seleccionadas por defecto y que el usuario debe revisar para evitar aceptar configuraciones que no desea
- La interfaz utiliza colores, tamaños y elementos visuales que compiten entre sí por la atención del usuario
- La presencia de ventanas emergentes y elementos superpuestos dificulta la interacción con los campos del formulario
- Algunos controles están colocados en posiciones poco esperadas, lo que aumenta el tiempo necesario para encontrarlos
- La página utiliza textos y mensajes que pueden resultar confusos, en lugar de ofrecer instrucciones directas sobre cómo completar cada paso
- El usuario debe realizar demasiadas comprobaciones para completar correctamente una tarea sencilla como registrarse
- La interfaz introduce **fricción innecesaria** mediante requisitos, mensajes y controles que complican el proceso de registro
- La falta de una estructura visual clara hace que sea difícil distinguir entre instrucciones, campos y acciones
- Los errores de introducción pueden obligar a repetir pasos del formulario, aumentando el tiempo necesario para completarlo
- La experiencia de usuario resulta frustrante porque la página dificulta intencionadamente acciones que normalmente deberían ser sencillas

## Ejercicio inicial: prototipo y wireframe de un sitio web
Diseñar el [prototipo/wireframe](https://www.figma.com/design/b1ugYM6eswy5jVuc3fvNGH/Shruk-Store?node-id=0-1&t=4m4zszJF1dEVIAQD-1) (según la fase) de una nueva página de inicio, cumpliendo estos requisitos:
- Banner promocional
- Barra de navegación intuitiva
- Secciones destacadas de productos
- Encabezado con navegación
- Zona de héroe (destacado)
- Listado de contenido principal
- Sección de donaciones/voluntariado (o equivalente según el sitio)
- Pie de página
- Uso de herramientas de diseño (Sketch, Balsamiq, Figma)
- Debe garantizar usabilidad y estética a la vez

Junto a cada bloque debe rotularse a qué fase de desarrollo pertenece: **área de redacción**, **área técnica** o **área artística**
